# FDE组织方法论：打造最接近客户结果的AI交付团队

> 写给政府信息化负责人与企业技术决策者的 AI 交付组织方法论。

[![License: CC BY-NC-SA 4.0](https://img.shields.io/badge/License-CC%20BY--NC--SA%204.0-lightgrey.svg)](https://creativecommons.org/licenses/by-nc-sa/4.0/deed.zh)

## 关于本书

这是一本讨论"组织"而非"算法"的书。大语言模型（Large Language Model，LLM）让"做出一个令人惊艳的演示"变得空前便宜，但把演示变成客户财务报表上的一行数字依旧空前困难——Gartner 预测至少 30% 的生成式人工智能项目将在概念验证后被放弃，波士顿咨询的调研显示 74% 的公司尚未从人工智能的使用中展现实际价值。杀死这些项目的因素集中在数据、流程与组织层面，而不是模型能力本身。

本书的答案是**前线部署工程师（Forward Deployed Engineer，FDE）**：一种嵌入客户组织、依托可复用的平台底座、对"从发现问题到生产采用"全程负责的工程角色，以及围绕它的一整套交付方法论、组织设计与商业模式。全书以"认识—方法—组织—实战—战略"五篇递进展开，回答一个问题：**怎样打造一支最接近客户结果的 AI 交付团队。**

- 篇幅：约 16.7 万字，前言 + 14 章 + 附录
- 图表：56 幅插图、98 张表格
- 参考文献：90 条，按 GB/T 7714 著录
- 案例原则：书中案例与数据全部来自可公开检索的真实来源（公司官方案例库、政府公开信息、年报、主流媒体报道、官方招聘文本等），关键数据均交代统计口径

## 这本书为谁而写

本书不面向初级工程师，不解释编程入门知识，预设读者具备企业信息化与软件工程的常识。它写给四类人：

| 读者 | 典型痛点 | 本书回答的问题 |
|---|---|---|
| 政府信息化部门负责人 | 项目要过立项、审计与绩效评价，但"建成即闲置"屡见不鲜 | 如何把"结果"写进采购与验收，如何识别换马甲的驻场外包 |
| 企业 CTO、技术 VP、IT 总监 | 功能清单漂亮、业务部门不认账；自建还是外购举棋不定 | 如何组织一支对结果负责的交付力量，如何让技术投入算得出账 |
| 数字化转型项目决策者 | 投过钱、踩过坑，面对新一波人工智能不敢再签 | 如何选对问题、设定毕业标准、设计按结果付费的合同 |
| 信息化企业负责人、FDE 团队负责人、人力资源部负责人 | 项目制毛利被定制吃光；新岗位不会招、不会定薪、留不住人 | 这支队伍怎么设计、怎么招、怎么激励、怎么收费 |
